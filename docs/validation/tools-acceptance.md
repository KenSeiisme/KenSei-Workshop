# 28 工具验收与维护

本轮目标是修复功能、输出和操作理解问题，不增加工具或游戏。功能正确、操作顺手和用户理解分别记录；自动化通过不代表真实手机、Google 授权或首次使用者测试通过。

## 运行

先安装锁定依赖和 Playwright 的 Chromium、Firefox、WebKit，构建网站并开启本机预览。普通验收只接受 localhost；正式站使用显式的 live 命令。

```powershell
pnpm install --frozen-lockfile
pnpm exec playwright install chromium firefox webkit
pnpm build
pnpm preview
# 在另一个终端运行：
$env:TEST_BASE_URL = 'http://127.0.0.1:8769'
pnpm test:tools:smoke
pnpm test:tools:acceptance
```

- `test:tools:smoke`：28 工具对应的核心批次流程、双语页面和保存竞态；不是完整边界验收。
- `test:tools:acceptance`：去重复用历次单元、数据库、文件输出、边界、同步、恢复、双语和布局测试；额外检查 Firefox/WebKit 的实际文件输出。
- `test:tools:live`：正式网址双语入口与匿名后端权限检查。页面检查使用隔离游客配置；另一个脚本使用真实公开配置检查服务器。不会把模拟账号标成真实 Google 授权。
- `TOOLS_BROWSERS` 可指定 `chromium,firefox,webkit,msedge,brave`；Brave 使用本机安装路径，可用 `BRAVE_PATH` 覆盖。可选浏览器未安装时报告 blocked，不算通过。
- `TOOLS_ACCEPTANCE_FILTER` 可按文件名筛选复验；筛选报告中未运行的功能保持 pending。
- 长时间验收可用 `python scripts/serve.py 8769 --quiet`，减少预览日志。真实完整测速只在显式设置 `RUN_REAL_NETWORK_TEST=1` 后运行 `node scripts/verify-network-online.cjs`；一次最多 500 MB 加协议开销，普通测试不会执行。有本轮真实测速报告时不默认重复整次测试。
- `_qa/tools-acceptance/<时间>-<模式>/` 保存逐项日志、JSON 和 Markdown 报告，目录不进入部署。失败保留截图，不记录凭证、密码或私人请求正文。

当前目录清单由 `tests/acceptance/tools.json` 对应 28 个目录标识；增加或遗漏工具会让验收入口失败。核心流程有公开的合成 CSV、字幕和参考值样本，位于 `tests/fixtures/acceptance/`。

本轮结果见 [2026-10-28 验收报告](2026-10-28-tools-acceptance.md)。命令报告中的 `functional` 以完整深度组为准，smoke 或筛选运行未执行的深度检查仍显示 pending；核心检查的实际通过项见对应套件日志。

## 检查方法

| 层次           | 证据                                                        | 不替代的检查                         |
| -------------- | ----------------------------------------------------------- | ------------------------------------ |
| 单元           | 独立参考值、边界、确定性算法                                | 浏览器实际操作                       |
| 本地数据库     | 完整迁移、角色上下文、RLS、冲突和重试                       | 正式配置及真实 Auth/Realtime         |
| 浏览器文件输出 | 图片像素、ZIP 解包、PDF 页序/文字、音频 PCM、实际下载       | 实体设备及外部阅读器人工观察         |
| 跨浏览器       | 三种引擎的双语/布局/Help；Firefox/WebKit 同一组文件输出断言 | 实体 iPhone Safari 或 Android Chrome |
| 账号模拟       | 登录返回、过期、跨账号缓存及保存竞态                        | 真实 Google 账号授权                 |
| 开发者走查     | 首屏任务、入口、按钮、错误与保存说明                        | 首次使用者理解情况                   |

普通文件测试不允许上传。Network Test 的 Cloudflare 流量、账号同步与共享白板属于明确联网能力，分别检查端点和权限。真实完整测速、真实四人房间及物理录制使用独立受控检查；未执行则标待实测。

## 易用性验收

每个工具用清单中的任务检查用途、输入、主操作、结果、错误恢复和保存位置。用户能否找到当前步骤，比按钮是否存在更重要。简单工作区优先保留常用操作；进阶 SQL、配方和多轨能力继续按需打开。

页面加载、Help、语言及标签切换不能自动启动测速、录制或测试。开始处理后取消/失败保留输入；旧结果标示待更新。手动保存期间的新编辑不能误报已保存，账号变化后不得沿用旧记录标识。

布局覆盖 320/360/768/1024/1440px 和短横屏。放大、软键盘、实际触控与屏幕阅读器在人工清单另外记录；不能把改变视口称为真实设备测试。

## 缺陷与发布门槛

- **P0**：越权、敏感数据泄露或大范围不可恢复数据损失，立即阻断发布。
- **P1**：主要流程不可用、输出错误、误报保存或取消后丢失有效内容，修复并通过针对性回归后发布。
- **P2**：难以发现的入口、误导说明、键盘/标签障碍或次要兼容问题，修复或明确记录受影响能力与替代方式。
- **P3**：不影响理解和操作的视觉细节，可单独排期。

每个缺陷记录环境、步骤、样本、预期与实际、证据、修复及复验；不通过降低断言掩盖失败。历史测试过时或时序不稳定时保留原业务断言，修正等待和输入前提。

28 工具核心流程与关键输出必须通过，且不得存在已知 P0/P1。人工项目保留独立状态，不宣称“零 Bug”或“全部真实设备通过”。修改源文件与模板，重新构建；发布沿用现有 GitHub 分支和 Vercel 自动部署，部署后再复查实际网址。

## 人工短清单

站主已选择 **Android 手机**，主人工清单按 Android Chrome 执行；iOS Safari 维持独立待实测，不把桌面 WebKit 当作 iPhone。每项记录手机/电脑型号、浏览器、语言、日期及通过/失败。使用合成样本，不需要提供 Google 密码。

- [ ] **Google 登录**：从繁中工具页登录，取消一次再重试；返回原页，不自动开始测试。退出后私人记录不显示；换另一个账号不串资料。
- [ ] **手机文字与下载**：打开 Text Toolkit，输入中英文，切换语言和横竖屏；软键盘不挡住操作。保存命名草稿，重新打开核对文字，再下载 TXT。
- [ ] **文件工作流**：Image Studio 处理两张非私人图片，比较和下载；把结果 Send to PDF，原页保留，目标页不自动处理。
- [ ] **扫码与录音**：主动开相机/麦克风，先拒绝再重试；停止、切页后设备指示灯关闭。试听录音，下载后在本机播放器打开。
- [ ] **录屏**：选择窗口/标签页，检查有/无共享音轨、暂停继续、浏览器停止共享及下载播放；不支持的手机应明确说明。
- [ ] **共享白板**：四个测试身份验证同时绘画、断线、重连、第五人拒绝及移除成员；完成后清理测试房间和账号。仅创建临时测试数据，不使用真实学习资料。
- [ ] **完整测速**：只启动一次，记录消耗；检查取消和单位，复制报告不包含完整 IP。不可把模拟曲线标成真实线路测量。
- [ ] **键盘与读屏**：用 Tab/Shift+Tab、方向键、Enter、Escape 完成一次工具任务，听取输入名称、错误及完成状态；没有焦点陷阱。
- [ ] **首次使用者（另行安排）**：不解释按钮，让其完成清单任务，记录找不到入口、误解保存或需要提示的位置。开发者及站主熟悉流程的走查不冒充此项。
